# 08. 주가 수집 라이브러리 검토

> **검토일: 2026-09-15.** 한국 주가에 FinanceDataReader, 미국 주가에 yfinance를 쓸 경우 [07-price-ingestion.md](07-price-ingestion.md)의 직접 호출 설계와 무엇이 달라지는지 검토한 기록이다. 수치는 모두 이날 라이브러리를 설치해 직접 호출한 결과다.

## 1. 결정

| 시장 | 결정 | 라이브러리가 맡는 데이터 |
| --- | --- | --- |
| US | **yfinance 채택** | 종가, 분할 이벤트, 거래일 캘린더, 복수 클래스 7개 라인의 현재 주식수 |
| KR | **FinanceDataReader 제한 사용** | 과거 상장주식수(2026-03-09 이후), 상장폐지 목록, KOSDAQ 소속부. 가동 후 일별 주식수의 교차검증·대체 |

한국은 **직접 호출로 얻을 수 없거나 직접 호출 결과에 결함이 있는 데이터에만** FinanceDataReader를 쓴다. 한국 종가(무수정·수정)는 네이버 직접 호출을 유지한다.

이 결정에 따라 바뀐 설계는 [07](07-price-ingestion.md)에 반영했다. 바뀐 내용은 [§7](#7-07-문서에-반영한-변경)에 정리했다.

## 2. 검토 방법

| 항목 | 내용 |
| --- | --- |
| 환경 | 임시 가상환경, Python 3.12.7 |
| 버전 | finance-datareader 0.9.202, yfinance 1.7.0 |
| 호출 경로 확인 | 설치된 패키지 소스를 읽어 각 함수가 실제로 호출하는 주소를 확인 |
| 비교 기준 | 07 문서에서 검증한 직접 호출 결과. 네이버 무수정·수정 종가, Yahoo 차트 API, Daum 상장주식수, SEC 공시 주식수, Nasdaq 종가 |
| 표본 | 한국 WI26 구성종목 2,373개 스캔 결과, 미국 S&P 500 503개 라인 |

두 라이브러리 모두 **새 데이터 출처가 아니다.** 07 문서가 직접 호출하는 출처나 그 출처를 미리 받아 둔 캐시를 감싼 것이다. 따라서 검토의 초점은 데이터 품질보다 기능 범위, 운영 편의, 의존성이다.

## 3. FinanceDataReader 검토

### 3.1 호출 경로

| 함수 | 실제 호출 |
| --- | --- |
| `DataReader("005930")` 등 한국 종목 | `fchart.stock.naver.com/sise.nhn?timeframe=day&count=6000` (네이버 차트 API) |
| `DataReader("KS11")` | GitHub `FinanceData/fdr_krx_data_cache`의 `data/index` 파일 |
| `StockListing("KRX")` | `data.krx.co.kr`에서 최근 영업일(`max_work_dt`)만 조회한 뒤, 같은 GitHub 캐시의 `data/listing/krx/{날짜}.csv` |
| `StockListing("KRX-DESC")` | 같은 캐시의 `data/listing/desc` |
| `StockListing("KRX-DELISTING")` | 같은 캐시의 `data/listing/delisting` |

- KRX 정보데이터시스템을 직접 호출하는 함수도 코드에 남아 있지만 기본 경로가 아니다. KRX 지수 직접 호출 코드는 "authenication required" 주석과 함께 비활성화돼 있다.
- 최근 영업일 조회는 로그인 없이 동작했다. 캐시는 FinanceDataReader 운영자가 KRX에서 받아 올리는 파일이다.

### 3.3 장점

- **과거 상장주식수를 무인증으로 얻는다.** 날짜별 KRX 스냅샷을 주는 무인증 출처는 이 캐시뿐이었다. 07 문서의 G-1 공백이 2026-03-09 이후만큼 줄었다.
- **상장폐지 목록이 정확하다.** 6자리 종목코드, 증권 종류, 폐지 시점 상장주식수가 함께 온다.
- **전 종목을 한 번에 받는다.** 파일 하나로 전 종목 주식수가 오므로, 종목마다 호출하는 Daum 경로의 교차검증과 대체 경로가 된다.
- **폐지 종목의 수정 종가를 보존한다.** 네이버 `siseJson` 직접 호출과 같은 성질이다.

### 3.4 단점

- **원종가를 주지 않는다.** 시가총액에 필요한 무수정 종가는 여전히 네이버 모바일 API를 직접 호출해야 한다.
- **종가 기능은 직접 호출과 값이 같다.** 라이브러리를 거쳐도 얻는 데이터가 늘지 않는다.
- **캐시 이력이 짧다.** 2025-01-02 ~ 2026-03-06 구간은 여전히 비어 있다.
- **당일 파일의 가격을 믿을 수 없다.** 마지막 갱신 시각이 일정하지 않다.
- **특정 날짜 조회 함수가 없다.** `StockListing("KRX")`는 최신 파일만 읽는다. 과거 날짜는 캐시 주소를 직접 읽어야 한다.
- **개인 운영 캐시에 의존한다.** 운영자가 갱신을 멈추면 경로가 끊긴다.

### 3.5 채택 범위

| 데이터 | 사용 | 이유 |
| --- | --- | --- |
| 무수정 종가 | 안 함 | 제공하지 않는다 |
| 수정 종가 | 안 함 | 네이버 `siseJson` 직접 호출과 값이 같다 |
| 과거 상장주식수 (2026-03-09 ~ 가동 전일) | **함** | 대체 가능한 무인증 출처가 없다 |
| 상장폐지 목록 | **함** | KIND 페이지에 종목코드와 증권 종류가 없다 |
| KOSDAQ 소속부 (SPAC 판별) | **함** | KIND 목록에 없다 |
| 가동 후 일별 상장주식수 | 교차검증·대체 | Daum 직접 호출로 당일 값을 얻을 수 있다 |

## 4. yfinance 검토

### 4.1 호출 경로

| 기능 | 실제 호출 |
| --- | --- |
| `download`, `Ticker.history` | Yahoo 차트 API. 07 문서가 직접 호출하던 것과 같다 |
| `Ticker.info` | Yahoo quoteSummary API. 쿠키와 crumb 토큰이 필요하며 라이브러리가 발급 절차를 처리한다 |
| 캐시 | 기본값은 사용자 캐시 폴더 아래 `py-yfinance`. `yf.set_tz_cache_location()`으로 바꿀 수 있다 |

같은 quoteSummary API를 표준 라이브러리로 직접 호출하면 HTTP 401 `Invalid Crumb`가 났다. v7 quote API도 401이었다. crumb은 계정 인증이 아니라 세션 토큰이다.

### 4.2 검증 결과

**종가와 분할**

| 항목 | 결과 |
| --- | --- |
| `download` 기본값 | `auto_adjust=True`, `actions=False`, `threads=True`, `repair=False` |
| 503종목 2025-01-01 이후 일괄 다운로드 | 36.4초. 결과 425행. 빈 종목 0 |
| 결측 | 상장 전 구간 943셀 (FDXF, HONA, Q, SNDK), 상장 후 결측 1셀 (FISV) |
| NFLX 10:1 분할 | 2025-11-14 `Close` 111.217, 2025-11-17 `Stock Splits` 10 |
| KO, `auto_adjust=False` | 2025-01-02 `Close` 61.84, `Adj Close` 59.2749 |
| KO, 기본값 | 2025-01-02 `Close` 59.2749. `Adj Close` 컬럼 없음 |
| `Ticker.history` 인덱스 | `America/New_York` 시간대 |

| --- | --- |
| NFLX | 90개 시점, 2025-01-04 ~ 2026-07-21. 분할 이후인 2025-11-13에도 423,732,334로 공시 원값 |

- `info`는 클래스별 현재값을 준다. FOXA+FOX, NWSA+NWS는 회사 합계와 정확히 같다.
- GOOGL+GOOG는 회사 합계보다 835,779,041주 적다. 상장되지 않은 Class B로 보인다.
- NFLX `info` 값은 SEC 2026-06-30 공시값과 같다. `info`가 공시 주기로 갱신되는지, 분할 직후 바로 바뀌는지는 확인하지 않았다.

### 4.3 장점

- **코드가 크게 줄어든다.** 503종목을 한 번의 호출로 받는다. 요청 병렬화와 JSON 파싱을 직접 만들 필요가 없다.
- **분할 이벤트가 종가와 같은 표로 온다.** `actions=True`로 받으면 `Stock Splits` 컬럼이 붙는다.
- **복수 클래스 주식수를 자동으로 받는다.** 07 초안에서 수기 입력하기로 했던 7개 라인을 매일 스냅샷으로 받는다. 가동 전 구간은 가동일 값으로 근사한다.
- **엔드포인트 변경을 업데이트로 따라갈 수 있다.** Yahoo가 쿠키·토큰 절차를 바꾸면 라이브러리 업데이트로 대응한다.

### 4.4 단점

- **기본값이 배당 조정 종가다.** 이 시스템의 수익률 정의와 어긋나므로 `auto_adjust=False`를 반드시 줘야 한다.
- **상장폐지 종목은 여전히 없다.** 같은 API이므로 07 문서 G-2의 10종목 공백은 그대로다.
- **실패가 조용하다.** 이력이 없는 티커도 예외 없이 빈 결과를 준다. 호출 후 빈 컬럼을 검사해야 한다.
- **주식수 이력은 보완되지 않는다.** `get_shares_full`은 단일 클래스에서 SEC와 같은 분기 공시값이고, 복수 클래스에는 회사 합계 수준 값을 준다.
- **한국 종목에는 쓸 수 없다.** 같은 Yahoo 차트 API라서 07 문서 §3.2의 한국 종가 오류가 그대로 나온다.

### 4.5 채택 범위

| 데이터 | 사용 | 비고 |
| --- | --- | --- |
| 종가·거래량 | **함** | `auto_adjust=False`, `actions=True` |
| 분할 이벤트 | **함** | 주식수 비율은 SEC로 확인 ([§6](#6-추가-발견-yahoo-분할-이벤트의-분사-혼입)) |
| 거래일 캘린더 | **함** | `^GSPC` |
| 복수 클래스 7개 라인 현재 주식수 | **함** | `Ticker.info`, 매일 스냅샷 |
| 단일 클래스 주식수 | 안 함 | SEC 공시값 유지 |
| `get_shares_full` | 안 함 | 복수 클래스 값이 회사 합계 수준 |

## 5. 공통 영향

**의존성**

두 라이브러리를 설치하면 아래 32개 패키지가 설치된다. 기존 수집 스크립트는 표준 라이브러리만 쓰므로, 이 모듈만 프로젝트 가상환경에서 실행하고 버전을 고정한다.

## 6. 추가 발견: Yahoo 분할 이벤트의 분사 혼입

- **정수비 이벤트는 실제 분할·병합이었다.** 비교 가능한 10건 모두 주식수가 Yahoo 비율만큼 바뀌었다. 차이는 분기 중 자사주 매입·발행분이다.
- **정수비가 아닌 이벤트는 대부분 분사 조정이었다.** 비교 가능한 7건 중 6건은 주식수가 그대로였다. DuPont 2.39와 WDC 1.323은 각각 Qnity, Sandisk 분사로 알려진 시점과 겹친다. 분사 사실은 이번 검토에서 공시로 확인하지 않았다. yfinance의 SNDK 거래 이력은 2025-02-13부터 있다.
- **예외가 있다.** HON 2026-06-29는 비율이 0.9535인데 주식수는 절반이 됐다. 같은 날 Honeywell Aerospace(HONA)가 S&P 500에 편입됐다. 분사와 주식수 감소가 한 비율로 합쳐진 것으로 보이며, 세부 내용은 확인하지 않았다.
- **가격 역산에는 문제가 없다.** Yahoo가 과거 가격을 같은 비율로 조정했으므로 같은 비율로 되돌리면 된다.
- **주식수 계산에는 문제가 된다.** 모든 이벤트에 비율을 곱하면 DuPont의 2025-11-03 주식수가 2.39배로 부푼다.

07 문서 §8.3에 판정 규칙을 넣었다. 정수비 이벤트만 주식수에 반영하고, 그 밖의 이벤트는 주식수에 반영하지 않고 특이사항으로 기록한다.
